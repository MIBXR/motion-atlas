## 〇、摘要

- **用户怀疑属实**：改动前“首拍偏移”只改表格和刻线，**声音完全不动**；“半拍 / 十六分”只改吸附表，**拍点条不画细分网格、节拍器也不放细分**；事件本身**不发声**，所以 A/B 差别既听不到也看不清。另有播放头每圈漂移 150ms、改速要晚一拍才生效、卡顿后一串补发等问题（第一节，全部实测）。
- **节拍器重做**：以“拍”为单位的音乐时钟 + 150ms 前瞻调度，声音全部走 `MotionKit.audio` 的音色与混音链；4 组音色（鼓组 / 木块 / 电子 / 机械）× 四个层级（小节重拍 / 次强拍 / 拍 / 细分），三级音量可调；拍号 2/4、3/4、4/4、5/4、6/8、7/8（含 3+3、2+2+3 分组的次强拍）；细分 拍 / 半拍 / 三连音 / 十六分；摇摆 0–100%；打拍测速（点按或 T 键）。改速度 / 拍号 / 细分 / 摇摆从“此刻 + 15ms”起生效，相位连续、不重启。
- **吸附可听可见**：1 / 2 / 4 小节的循环时间线（网格随细分、摇摆、偏移即时重绘，A 道原始、B 道吸附后、箭头标出移动），事件用打击音播放，播放方式“只听节拍器 / A / B / A/B 交替 / A+B 叠放”；首拍偏移让网格与重拍整体平移，并有“循环起点提示音”让偏移直接听得见；量化强度 0–100%；5 组示例（拖拍、切分、三连音、摇摆、剪辑点）各带一句提示和“试一试”按钮；小球演示“落在拍上 / 反拍 / 没踩准”；打拍板实时显示早晚毫秒，“录入一遍”录下一整圈后自动 A/B 交替；延迟补偿与一键校准。
- **曲线 × 时长 × 拍子**：预览可跟随节拍每小节重播，“落点踩重拍 / 起步踩重拍”，起步呼啸、每个元素落定一声提示音；“对到拍”按钮把时长设成 ¼ / ½ / 1 拍、错峰设成网格步长；线性对照、频闪轨迹；拖拽 / 键盘 / 数值 / 预设逐项修好并测过。
- **导出**：CSS / MotionKit / Prompt 与全部参数同步（拍号、速度、细分、摇摆、量化强度、偏移、吸附后事件；MotionKit 片段含可直接运行的 `pattern()` 节拍器乐谱与事件乐谱）；新增“导出 WAV”（与页面同一个乐谱生成函数离线渲染整数圈）。
- **验证**：功能测试 59/59、曲线面板 14/14；30 秒精度测试排程误差 0、漂移 0、无漏拍 / 重复、Web Audio 实际 `start()` 时刻 255/255 一致；画面切换从不早于声音（中位 6ms、最大 17ms ≈ 一帧）；16 段 WAV 峰值 -3.5～-7.4 dBFS、0 削波，节拍器起音距理想网格 ≤ 0.33ms；3 种视口 × 浅 / 深色 × 6 个位置 + 22 张交互过程截图，无横向溢出、0 报错；运行时最小字号 12px；`node scripts/check.mjs` 通过。

### 1.2 kit 音频 API（`kit/motion-kit.js` 2.0、`docs/pipeline.md` 第四节、`dev/reports/T1.md`）

- 能直接用的：37 个合成音色与 `audio.meta` 校准电平、总线 / 压缩 / 软削波天花板、`play()` 即时触发并返回 `{ stop }`（未开始的声部会被静默取消）、`define()` 自定义音色、`renderOffline()` + `wav()`、`pattern()`（div、swing、X/x/o 力度）。
- **`attach(timeline, score)` 不适合节拍器**：它把乐谱绑在以秒为单位的时间轴上，改 BPM 要么整份重排、要么相位跳变；时间轴每帧最多走 0.1 秒、以 80ms 容差重新对齐，不是样本级。
- **`play()` 只接受相对延迟**：内部 `when = ctx.currentTime + 0.005 + delay`，会再读一次 `currentTime`，跨渲染量子时有 2.7ms 误差。实验室用 `define('lab:at', …)` 注册一个包装音色，把 kit 传入的时刻换成我们算好的绝对时刻 `at`，同一套音色、同一条混音链，`start()` 时刻逐个精确（见 4.2）。
- **压缩器延迟**：主链路 `DynamicsCompressorNode` 在浏览器里是固定 6ms 预读。离线 WAV 实测所有起音比乐谱晚 288 个样本（48kHz）。实时输出同样晚 6ms。
- 默认电平：`kick` 的能量在 48Hz，笔记本扬声器几乎放不出来；`tick` / `blip` 相对鼓组偏小。实验室用每层增益修正 `g` 重新平衡（1.4 节、4.4 节）。

## 二、设计

### 2.1 页面结构（学习路径）

`头部（4 步导航）→ 吸顶走带（播放、BPM、打拍测速、拍灯、位置、声音与音量）→ 01 感受节拍 → 02 理解吸附 → 03 曲线 × 时长 × 拍子 → 04 导出`。每一步标题下一两句说明它在教什么。网格（细分）与摇摆在 01 和 02 各有一份控件，绑定同一个状态——听到的格子就是吸附的格子。手机上走带压成两行（约 100px），声音按钮只留图标（读屏名称保留）。

### 2.2 音乐时钟与调度

- 位置 `p`（拍）= `p0 + (t − t0) / 每拍秒数`，`t` 取 AudioContext 时间（出声时）或 `performance.now()`（静音 / 被挡住时），两者切换时按当前位置重新锚定，画面不跳。
- **改速度、拍号**：以 `ref = now + 15ms` 为锚点，`p0 = 旧时钟在 ref 的位置`、`t0 = ref`；晚于 ref 的已排程声音全部 `stop()`（未开始的被 kit 静默取消），游标退回 ref，按新参数重排。**其他参数**（细分、摇摆、偏移、强度、模式、音量、事件）时钟不动，只取消并重排。
- 拍号切换：当前小节已走过的拍数小于新拍号的拍数就继续数，否则下一拍当作新小节的重拍（小节起点始终是整数拍）。
- 排程：`gen(a, b)` 返回位置 ∈ [a, b) 的全部声音事件（节拍器、A/B 事件、循环起点提示、曲线提示音），**实时与离线 WAV 共用**。时刻 = `t0 + (pos − p0) × 每拍秒数`，从锚点直接计算，不累加，因此不漂移；早于此刻的一律不排（卡顿后不会补发）。
- 画面：每帧用 `getOutputTimestamp()` 把“此刻输出的样本”换成 AudioContext 时间，再减去压缩器 6ms（`PROC`），得到“听到的”位置；节拍格、小球、播放头、命中闪光、曲线预览都由它驱动。输入事件用 `event.timeStamp` 换算到同一时间轴。

### 2.3 片段（循环）与事件

- 循环 = 1 / 2 / 4 小节，长度 `L`；事件时刻是相对循环起点的秒数（与剪辑软件一致）。片段时间 `C = o + (p − 小节起点) × 每拍秒数`（`o` = 首拍偏移），第 `m` 圈的事件位置 = `小节起点 + (m·L + 时刻 − o) / 每拍秒数`。
- 首拍偏移不移动节拍器本身（不打断律动），而是让网格与重拍相对片段平移：画面上网格整体右移、阴影标出偏移区；声音上事件与“循环起点提示音”相对拍子提前，偏移 300ms 时起点提示音在第一个重拍前 300ms。
- 吸附：最近的网格点（含摇摆后的位置），并保证吸附后不早于第 0 秒；强度 `s` 时 `snap = t + s × (full − t)`。多个事件吸到同一点时标“重叠”。落点分类：小节重拍 / 次强拍 / 正拍 / 反拍 · 切分 / 三连音 / 十六分弱位，位置写成“小节.拍.格”（时间线标尺、吸附明细、导出注释一致）。
- A/B 交替按片段圈数轮换；切到交替或载入示例时“这一圈”先放 A；录入结束后下一圈先放 A（你敲的）。

## 四、验证

### 4.1 功能测试（`func.mjs` → `func.txt`，**59/59 通过**）

用真实控件（range 的 input、按钮 click、CDP 键盘 / 鼠标事件）改参数，读页面调度日志 `__lab.LOG` 与时钟锚点按公式核对；`AudioScheduledSourceNode.start` 打桩核对 Web Audio 实际收到的时刻。要点：

- 默认声音关；点“播放”后声音开、时钟切到 AudioContext。
- 120 BPM 半拍：层级（重拍 / 次强拍 / 拍 / 细分）正确，排程时刻误差 0，`start(when)` 11/11 一致，提前量 80–149ms。
- 改 BPM 120→90：新锚点位置与旧时钟在锚点处的位置相同；改动后第一个格点在锚点后 166ms（旧速度会是 124ms），之后间隔恒为 333.333ms；旧速度下晚于锚点的声音被取消，无重复。
- 细分 拍 / 三连音 / 十六分的位置与间隔；摇摆 100% → 反拍 0.6667 拍、50% → 0.5833 拍；「拍」网格下摇摆禁用。
- 拍号 3/4（重拍每 3 拍、无次强拍）、6/8（第 4 拍次强拍），小节起点始终是整数拍。
- 剪辑点示例吸附值（0.31→0.25 … 2.9→3.0）；A/B 交替每圈只放一种且轮换；A/B 事件时刻符合片段公式；A 与 B 时刻差 = 吸附偏差（-60, 10, -120, -50, 100ms）。

## 五、给主任务的 kit 建议

1. **`audio.play(name, { at })` 支持绝对时刻**。现在只有相对 `delay`，内部再读一次 `currentTime`，跨渲染量子时有一个量子（2.7ms）的误差，做节拍器、节拍游戏或任何“自己排程”的交互作品都会遇到。实验室用 `audio.define('lab:at', …)` 包装音色绕过（`assets/lab.js` 的“声音：按绝对时刻触发 kit 音色”一节），kit 原生支持后可以删掉。
2. **压缩器 6ms 预读延迟**：主链路 `DynamicsCompressorNode` 让所有声音（实时与 `renderOffline`）比乐谱晚 6ms（离线实测 288 样本）。对 47 个 Demo 来说不到一帧，但 `render.mjs --audio` 导出的 WAV 与画面系统性错开 6ms。建议 kit 暴露 `audio.latency`（处理延迟 + `outputLatency`），`renderOffline` 默认从 6ms 处截取（实验室用 `renderOffline(score, dur, { from: 0.006, preroll: 0.006 })` 实现了同样效果），`attach` 的调度器与 `__motion` 的画面时钟也可以据此对齐。
3. **“听到的”时刻工具函数**：`audio.heard()`（`getOutputTimestamp` 换算 + 处理延迟）与 `audio.timeOf(event.timeStamp)`，交互 Demo（打拍、节拍游戏、按住确认）都用得上。实现可直接移植 `lab.js` 的 `heard()` / `tapClock()`。
4. **`MotionKit.beats().quantize` 能力偏弱**：只支持 `div`，不支持摇摆、三连音之外的分组、强度与“不早于 0”。可以加 `quantize(t, { div, swing, strength, min })`；实验室导出目前直接给出吸附后的秒数，绕开了它。
5. **音色电平**：`kick` 在小扬声器上几乎听不到，`tick` / `blip` 相对鼓组偏小。建议在 `docs/pipeline.md` 的音色表里注明“重拍要叠中高频层”，或给 `kick` 加可选的 `click` 层力度说明。实验室的平衡数据见 4.4。

## 六、遗留问题与说明

1. **未经人耳试听**：本机无音频输出；音色平衡靠离线测量（峰值、400Hz 以上峰值、RMS、起音检测）。建议优先试听 `01`、`10`、`11`/`12`、`13`/`14`、`17`/`18`、`19`，必要时调 `KITS` 里的 `g` 与默认三级音量。
2. **只在无头 Edge 验证**：Safari 对 `getOutputTimestamp` 支持不完整时会退回 `currentTime − outputLatency − 6ms`；蓝牙耳机等高延迟设备靠“延迟补偿 / 按平均偏差校准”处理。
3. **事件按秒固定**：示例是按当前 BPM 生成成秒数的，之后改 BPM 事件不会跟着缩放（与剪辑软件一致，“剪辑点”示例的提示里写明了）。需要“按拍记录”的事件时可重新载入示例。
4. **默认开着的提示音**：第一次播放时除了节拍器，还会听到每 2 小节一声循环起点提示、每小节一次曲线提示音（呼啸 + 落定声），用来体现“动效带声音”；二者都在页面上一键可关（02 的“循环起点提示音”、03 的“提示音”）。如果主任务觉得 01 步应该更“纯”，把 `DEF.startCue` / `DEF.cue` 改为 `false` 即可。
5. `docs/guide.md` 与 `README.md` 里对实验室的一句话描述仍是旧的（调曲线、时长、错峰与 BPM 吸附……），不在 T3 范围，T13 统一更新时可补上“节拍器、A/B 吸附对比、打拍录入、WAV 导出”。
6. 站点共享的“回到顶部”浮动按钮在手机上会盖住滑杆右侧的读数一角（站点级，非实验室问题）。
