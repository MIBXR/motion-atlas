## 修复及验收依据

### smoke 声音能力

`__motion.audio` 只表示离线乐谱接口，`__motion.sound` 仅在 `expose()` 元数据显式提供时存在；六个旧巧思只创建 `sound()` 并把对象交给 `controls()`，因此原 smoke 会把它们标成无声音。当前 kit 的 `readyMsg()` 已将乐谱、元数据和 `KIT.usesSound` 合并到 `motion:ready.sound`。

`scripts/smoke.mjs` 在导航前监听该事件，按同一 `sound` 字段输出能力标签，另读乐谱接口区分乐谱和即时音效；无需改 kit 或手改任何副本。复现和修复对照为 boot-typing、beat-clock、charge-release、hold-confirm、alert-state、seal-stamp；corner-hud 作为无声音对照。两轮全量日志确认分类共 2 + 13 + 32 = 47。

### 地图 seek 顺序无关

地图任意定位的画面需要由目标时刻决定。收尾后退回前段时，独立背景层会残留；进一步的真实 seek 回归还定位了标签引线、缓存精度和地图投影的状态依赖。本次在地图脚本内完成五项修复：

1. `drawOutro()` 在提前返回前同时写回 `.outro-bg` 的当前 opacity / visibility，退回收尾前可立即隐藏背景。
2. `drawMarkers()` 在每个 marker 回调开头清空 `me.box`，避免提前退出后 `drawLeader()` 继续消费前一时刻的标签矩形。
3. `drawSpace()` 每次先更新当前透明度，再用缓存跳过 Canvas 重绘；12fps 星点缓存保留，透明度不再沿用同一舍入桶中的前一值。
4. 非实线路线的 `partialKey` 使用末点原始坐标，避免 `toFixed(6)` 把不同目标时刻合并，留下旧 GeoJSON 端点。
5. `applyCamera()` 在 `jumpTo()` 前按目标 zoom / latitude 同步地球与墨卡托投影状态，消除从城市退回低缩放后相机被上一投影状态限制的问题。

`dev/wip/T13/seek-consistency.mjs` 对真实页面执行 **await 来源 seek → await 目标 seek → 读取状态**。主口径使用横屏 960×540 / 竖屏 540×960，每画幅 100 个主目标，分别从 60s、0s 和固定 seed 的随机时刻返回；另加每画幅 5 次画幅 roundtrip 与 7 个缓存 / 卡片专项，共 **624 条**。目标包含场景开始 / 结束、标题持续时间终点及其前后0.01秒，按实际配置核对生成。实际分两批执行：78目标 / 492条和补齐结束边界的22目标 / 132条，生产源码未变，合并记录为 `seek/combined-summary.json`。关键可见 DOM、GL 路线源和相机均 **0 不一致**，控制台错误为 0。

比较没有归一化 DOM 的 transform、SVG `d` 或 inline 样式；只有 camera getter 的浮点数舍入至小数点后 9 位（1e-9）。两批累计 **75,570 条隐藏诊断差异**是 624 次比较中重复计入的隐藏后代或空 SVG 属性差异，不是 75,570 个独立节点，也不是有效可见失败。空路径 / 空 SVG 不绘制，隐藏后代受父层透明度或可见性抑制，再激活时按当前 t 复写；这些差异保留在结果中供检查，不要求不可见子树字节相等。

原生画幅另测横 1920×1080 / 竖 1080×1920，目标 3.105、18、41.8s，各走三种来源，共 **18 条**，同样 0 关键可见 DOM / GL 路线 / 相机不一致和 0 错误。实际 runtime 为 scale=1、pixelRatio=1、AA 开启、正常精度测量间隔 6；18s 的正序及三种来源截图共 8 张位于 `seek/native/`。该结果验证同一源码的不同 seek 顺序一致，不等同旧新版本的正序画面完全不变。
