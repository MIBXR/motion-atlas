## 〇、摘要

- **首屏完整可见**：详情页改为“左列舞台（工具栏 + 舞台 + 刻度条，并排时吸顶）/ 右列操作、标题与说明”。舞台框按画幅比例与视口高度实时计算，5 种视口下舞台与刻度条都在首屏内（改动前 10/10 张都要滚动才能看到刻度条）。
- **横屏舞台宽度**：1440×900 为 992px，1920×1080 为 1372px，满足 ≥ 960px。1280×720 与 1024×768 受高度限制只有 796 / 881px，取舍说明见 2.2。
- **画幅切换**：Demo 回报 `orients.length > 1` 时出现“横屏 16:9 / 竖屏 9:16”分段按钮（SVG 图标 + 文字）。点击后发 `motion:orient`，以 Demo 回报为准，保持当前时刻。选择会被记住（localStorage），切换案例时沿用，也支持 `#case/<id>?orient=portrait` 分享。旧 Demo 显示“16:9 · 自适应”标记，不出现切换。去掉了旧的三档尺寸。
- **竖屏布局**：舞台占满可用高度，节拍列表（含节拍说明）放在舞台右侧，刻度条横跨两者，右侧说明列获得更多宽度。
- **全屏**：用 Fullscreen API，舞台按 contain 铺满屏幕，工具栏与刻度条浮在上下，播放中静止 2.5 秒后淡出，Esc 退出；不支持元素全屏的浏览器（iPhone Safari）改用固定定位铺满窗口。
- **暂停按钮**：两个 SVG 常驻，用 `data-playing` 切换显隐，图标 `pointer-events: none`，只在状态变化时更新。CDP 真实鼠标连点 20 次：**改动前 90ms 与 5ms 两种按压都是 0/20，改动后在所有页面都是 20/20**。键盘空格在 4 种焦点场景下都是 20/20，不会重复触发。
- **声音开关**：工具栏里有醒目的“声音 关 / 开 / 待启用 / 开启中 / 无”按钮，开启时用强调色并显示电平表。click 里发 `motion:sound`，选择会被记住，每个新 iframe 在 `motion:ready` 后按记忆重发。`blocked` 时舞台上提示“点击舞台启用声音”。旧 Demo 同样可控，iframe 有 `allow="autoplay"`。
- **加载状态**：用 `motion:loading` 显示进度卡片，`motion:ready` 后隐藏；加载中可以拖动刻度条，就绪后不会被拉回 0。
- **其他修复**：手机端整页横向溢出、说明列表格撑出横向滚动、节拍跳转把页面滚走、`<main aria-live>` 让每帧时间刷新都触发朗读、刻度条连上 Demo 前隐藏导致布局跳动、能量曲线刻线缩放后发虚，等等，见第三节。

## 一、调研发现

### 1.1 改动前的详情页（`dev/shots/T2/before/`，`geometry.txt`）

| 视口 | 舞台框 | 刻度条位置 | 首屏可见刻度条 |
| --- | --- | --- | --- |
| 1440×900 | 788×648，顶边 y=388 | 1075–1231 | 否 |
| 1920×1080 | 978×778，y=390 | 1207–1327 | 否 |
| 1280×720 | 696×518，y=382 | 940–1095 | 否 |
| 1024×768 | 963×553，y=372 | 965–1085 | 否 |
| 390×844 | 464×608（比视口还宽） | 1215–1370 | 否 |

问题清单：

1. **舞台过大且位置太低**：舞台上方依次是吸顶操作条、大标题、标签、尺寸切换，舞台从 y≈388 才开始；舞台高度固定为 `min(72vh, 820px)`，不按比例。刻度条永远在首屏之外。
2. **暂停按钮丢点击**：`paint()` 每帧执行 `play.innerHTML = playing ? pause : play`，按下与抬起落在不同节点上，浏览器不派发 click。实测改动前 90ms 和 5ms 两种按压都是 **0/20**（`results/clicks.txt`；T1 在 kit 控制条上测到 5ms 有 6/20，站点这里的重绘更频繁）。
3. **三档尺寸**（适应面板 / 成片 1920×1080 / 手机 390）切换时会重新载入 iframe；改为固定画幅后这三档没有意义。
4. **没有声音开关**：声音只能在独立打开的 Demo 里开；iframe 里也没有加载状态。
5. **刻度条在连上 Demo 之前是 `hidden`**：出现时整列高度跳一下。
6. **节拍表跳转用了 `scrollIntoView`**：会把页面滚走。
7. **手机端整页横向溢出**：`.detail-grid` 在 ≤1100px 用的是 `1fr`，最小宽度等于内容的最小宽度（表格、标签），舞台被撑到 464px，整页变宽、视口被缩放（`innerHeight` 变成 1039）。
8. **可访问性**：`<main id="app" aria-live="polite">` 包着整页，刻度条的 `<output>`（隐含 `role=status`）每帧改时间文字，读屏会不停播报；筛选时整页重绘也会被整段朗读。
9. **刻度条细节**：节拍刻线是会被横向拉伸的 `<rect>`（`preserveAspectRatio="none"`），窄舞台下发虚；当前节拍没有高亮；拖动没有处理 `pointercancel`；没有悬停时间提示。

### 1.2 Design Atlas 的做法（源码 `design-atlas/demo-preview.js` + `atlas.css` + `cases-layout.css`；线上截图 `dev/shots/T2/design-atlas/`）

- 详情页是 `grid-template-columns: minmax(0,1fr) 355px`：左侧 Demo 面板占剩余宽度，右侧说明固定 355px（中等宽度时 290px）。
- `.demo-panel` 吸顶（`top: 页头高 + 18px`）。`DesignAtlasPreview.mount()` 用 ResizeObserver 加 `window.resize` 计算：`高度 = innerHeight − 页头高 − 工具栏高（frame 顶到 panel 顶的距离）− 36`，写到 `.frame-wrap` 的 `height` 上；“桌面 1440px”模式下 iframe 固定 1440 宽，用 `--preview-scale` 缩放，iframe 高度取 `内容高 / scale`。
- 这样算出的高度对应的是**吸顶之后**的状态：页面初始位置时标题区把面板往下推，实测 1440×900 下 frame 顶边在 y=445、高 714、底边 1159（超出视口），滚动约 280px 吸顶后才正好填满一屏。
- 可借鉴的是“按视口高度反推舞台高度，用 ResizeObserver 跟随，面板吸顶”。不足之处在于初始位置并不是一屏，比例也不固定（它的 Demo 是网页，可以是任意比例）。本站已经固定了 16:9 / 9:16，所以直接按比例算宽高，并把标题移到右列，让**初始位置**就完整一屏。

## 二、设计决策

### 2.1 布局

```
┌ 顶栏 68 ───────────────────────────────────────────────────────────────┐
│ [← 案例库][▭ 横屏 16:9 | ▯ 竖屏 9:16]      [🔈 声音 关][⤢ 全屏][↻][↗] │ [☆][复制 Prompt][资料包 JSON]（吸顶）
│ ┌────────────── 舞台（按比例） ──────────────┐                          │ 06 / CASE · id
│ │                                              │                          │ 标题 / 副标题 / 标签
│ └──────────────────────────────────────────────┘                          │ 概述 …
│ [▶][━━━━ 能量曲线 + 节拍刻线 ━━━━] 00:03.40 / 31.20                    │ 节奏结构 …
│ [00.00 倒数][02.50 …][05.00 …] → 横向滚动                                 │ …
└───────────────────────── 左列吸顶 ────────────────────────────────────────┘
```

- 左列 `.stage-col` = 舞台工具栏 + 舞台框 +（竖屏时的节拍列表）+ 刻度条，并排时 `position: sticky` 吸在顶栏下方。左列高度恰好是一屏，向下阅读说明时舞台和刻度条始终可见。
- 右列 `.info-col`：收藏 / 复制 Prompt / 资料包 JSON（并排时吸顶），然后是标题、标签、说明。标题从舞台上方移到右列，这是腾出首屏高度的关键（改动前它占了约 230px）。
- 上下排列时（手机、窄平板）顺序是舞台 → 刻度条 → 操作与标题 → 说明，和视频类应用一致。

### 2.2 尺寸算法（`layout()`）

```
可用高 H = innerHeight − 顶栏 − 上边距 16 − 工具栏 40 − 2×间距 10 − 刻度条（实测）− 下边距 16   （下限 200）
说明列最小宽 infoMin = clamp(340, 内容宽 × 0.24, 440)
横屏：并排宽 = min(内容宽 − 28 − infoMin, H × 16/9)，上下排列宽 = min(内容宽, H × 16/9)
      并排条件：并排宽 ≥ 960，或 ≥ 上下排列宽的 85%（不为了并排牺牲太多舞台）
竖屏：舞台高 = H（此时节拍条不在刻度条里，H 稍大），宽 = H × 9/16
      右侧放得下节拍列表（≥ 220px）就放在右侧（并排时列表最宽 360），否则节拍条回到刻度条下方
全屏：舞台按 contain 铺满屏幕（浮层不参与计算）
```

- 结果写成 CSS 变量（`--stage-col / --frame-w / --frame-h / --ifr-w / --ifr-h`）和 `data-layout="split|stack"`、`data-side`。只在值变化时写入。
- **不抖动**：节拍条高度（`--strip-h`）显隐前后用同一个“基础高度”计算，结果对它的显隐不敏感；工具栏不换行、固定高度；ResizeObserver 回调合并到下一帧。实测 9 次视口变化后 0.8 秒内都没有继续写入。
- **iframe 就是画幅框本身**：旧 Demo 在 16:9 框里按自适应排版；新舞台 Demo 的缩放比恰为 框宽 / 1920（无黑边）。竖屏在手机上宽度不够时，框比舞台宽，左右是黑边。
- **≥ 960px 的取舍**：横屏要到 960 宽，舞台需要 540 高，加上顶栏 68、工具栏与间距 76、刻度条 112、边距 32，视口至少要 **828px** 高。所以：
  - 1440×900、1536×864、1920×1080 都 ≥ 960（实测 992 / 1052 / 1372，`extra/`）。
  - 1366×768 为 881，1280×720 为 796，1024×768 为 881（上下排列）。这是“刻度条必须在首屏”带来的结果；需要看清 24px 舞台字时，用全屏（1280 宽屏幕上舞台 1280×720）。没有为此隐藏顶栏或刻度条。
  - 竖屏在 720 高的桌面视口只有 276 宽（36px 字约 9px），同样用全屏解决（720 高屏幕上为 405 宽）。

### 2.3 画幅

- 意向画幅的优先级：hash 参数 `#case/<id>?orient=` → 页面查询参数 `?orient=` → 上次的选择（`localStorage['ma-orient']`）→ 横屏。iframe 地址带上 `&orient=<意向>`，新舞台 Demo 一载入就是这个画幅（kit 的 URL 模式；宿主之后发的 `motion:orient` 仍然有效）。旧 Demo 会忽略这个参数。
- 舞台框在载入前按“已知支持竖屏”预判：只有条目有 `previewPortrait`（迁移后由 capture 生成）时才先按竖屏给框，否则先按 16:9。连上 `__motion` 后（在 ready 之前，读 `orients / orient`）以 Demo 为准。
- 点击切换：写记忆，把 `orient` 写进 hash（`history.replaceState`，不触发路由），发 `motion:orient`，由 Demo 回报的 `motion:orient` 更新界面。被拒绝时（`rejected`）提示“这个 Demo 只有横屏画幅”；如果 500ms 内没有回报，直接读一次 `__motion.orient`。
- “独立打开”链接会带上当前画幅。

### 2.4 声音

- 按钮状态：`off` 关 / `pending` 开启中 / `on` 开（强调色 + 三根竖条电平表）/ `blocked` 待启用（强调色描边 + 舞台顶部提示“点击舞台启用声音”）/ `none` 无（禁用）。
- 点击（或快捷键 M）：开 → 关；关 / 待启用 → 开。在 click 里发 `{type:'motion:sound', on}`，记住到 `localStorage['ma-sound']`（默认关，符合“默认静音”）。在 Demo 回报 `motion:sound` 之前显示“开启中”。实测无头浏览器第一次启动音频设备要 1.9 秒，所以兜底超时是 2.5 秒；兜底计时器带序号，不会清掉之后一次操作的状态。
- 每个新 iframe 在 `motion:ready` 后按记忆重发 `on:true`。站内切换案例时同源子框架继承父页面的激活，直接出声；全新载入（没有手势）时是“待启用”，用户点舞台（kit 的手势兜底）或点按钮即可。
- **`motion:ready.sound` 不完全可靠**：6 个旧巧思（alert-state、beat-clock、boot-typing、charge-release、hold-confirm、seal-stamp）把 `sfx` 只传给了 `controls()`，没有写进 `expose()`，所以回报 `sound:false`，但实际有声音。站点因此只对已迁移的固定画幅 Demo 采信 `sound:false`（显示“无”），旧 Demo 一律保留开关。
- 电平表：读 Demo 内 `MotionKit.audio.meter().peak`，只改竖条的 `transform`，不重建节点；减少动态时不动。

### 2.5 加载

- iframe 创建后 200ms 仍未就绪才显示加载层，避免快的 Demo 闪一下。开始显示“正在载入 Demo”（不定进度条），收到 `motion:loading` 后显示“正在预加载资源 42%”和进度条，`motion:ready`（或 `__motion.ready` resolve）后淡出。加载期间舞台框 `aria-busy="true"`。
- 加载层 `pointer-events: none`，刻度条在连上 `__motion` 后立即可用（在 ready 之前）。连上之前的拖动会先记下位置，连上后再 seek；kit 的 `start()` 不会把用户拖过的位置拉回去。
- 刻度条在载入前就按条目数据画出来（时长、节拍、能量曲线），所以连上 Demo 时布局不跳。

### 2.6 刻度条与节拍点

- 播放按钮：`SI.play` / `SI.pause` 常驻，`.play-btn[data-playing]` 切换显隐，SVG `pointer-events: none`。每帧只改 `head.style.left`（变化 > 0.005% 才写）、时间文字（变了才写）与 `aria-valuenow / valuetext`。当前节拍变化时才改 `aria-current` 和刻线高亮。全站 `.btn / .icon-btn / .tool-btn` 里的图标也都设了 `pointer-events: none`。
- 刻线改为 `<line vector-effect="non-scaling-stroke">`（任何宽度下都是 1px），当前节拍的刻线变为强调色 2px。能量曲线保留。
- 节拍条（横屏）：单行横向滚动，当前节拍高亮并只滚动列表自身（`scrollLeft`）；竖向滚轮在横向溢出时转为横向滚动，滚到头再交给页面；用户手动滚动后 4 秒内不自动跟随。
- 节拍列表（竖屏）：舞台右侧、与舞台等高，含节拍说明（条目里的 `note`）。
- 节拍来源：条目 `rhythm.beats` 优先，没有时用 Demo 回报的 `markers`；超出 Demo 时长的节拍点会被丢掉。
- 拖动：指针捕获，`pointerup / pointercancel / lostpointercapture` 都会结束拖动，seek 按帧合并。悬停（以及触屏拖动时）显示时间提示，靠近节拍点时显示节拍名。
- 跳转一律不滚动页面。并排时舞台吸顶，始终可见；上下排列且舞台已滚出视野时，点击说明里的节拍表会提示“已定位到 05.00，舞台在页面上方”。

### 2.7 键盘

- 生效范围：焦点在刻度条上、焦点在舞台列内、全屏中，或焦点在页面主体（body）且最近一次指针操作在舞台列内。点过右侧说明后，空格仍然用来滚动页面。
- 焦点在按钮或链接上时，空格和回车交给元素自己处理（不会重复切换）。焦点在 Demo 里时，按键由 Demo 自己的快捷键处理（父页面收不到，所以也不会重复）。
- 空格：播放 / 暂停；← / →：跳 1 秒；Shift + ← / →：上 / 下一个节拍点；Home / End；F：全屏；M：声音。伪全屏时 Esc 退出（包括焦点在 Demo 里时）。

## 五、遗留问题与给后续子任务的说明

### 给主任务 / kit（T2 不改 kit，建议由主任务决定）

1. **`motion:ready.sound` 漏报**：kit 的 `readyMsg` 用 `!!(tl.__score || tl.sound)`，只看 `expose()` 的 meta。6 个旧巧思把 `sfx` 只传给了 `controls()`，回报 `false`。建议 kit 在 `sound()` / `audio.play()` / `controls({ sound })` 被调用时记一个“用到了声音”的标记并计入 `sound`。在此之前，站点对旧 Demo 一律保留开关；对已迁移 Demo 采信 `sound:false`（显示“无”并禁用）。
2. **加载进度到 100% 的消息**：最后一个任务完成时 kit 先发 `motion:loading 1`、再发 `motion:ready`，站点通常来不及显示“准备播放”就隐藏了，不影响使用。

### 给 T4–T12（迁移案例与巧思）

1. **声音要让站点知道**：挂了乐谱（`audio.attach`）的 Demo 会自动回报 `sound:true`。只用 `audio.play()` 做交互反馈音的 Demo，请 `expose(tl, { sound: true })`，否则站点会显示“无”并禁用开关。
2. **节拍点**：站点优先用条目的 `rhythm.beats`（带 `note`，竖屏时显示在舞台右侧列表里），没有时用 Demo 的 `markers`。迁移后如果调整了时长，请同步条目节拍，超出时长的节拍点会被站点丢掉。
3. **竖屏支持的提示**：条目有 `previewPortrait`（`capture.mjs` 生成）时，站点在载入前就按用户的竖屏意向给出 9:16 框；没有时先按 16:9，连上 Demo 后再切。迁移完成后请重新生成预览图，避免竖屏用户看到一次框的切换。
4. **嵌入时的尺寸**：iframe 正好是画幅比例的框（横 16:9、竖 9:16），kit 的缩放比为框宽 / 1920（或 / 1080），没有黑边。手机竖屏时框比舞台宽，左右黑边是站点画的。
5. **验证方式**：Demo 迁移后可直接在 `cases.html#case/<id>?orient=portrait` 查看；也可以复用 `dev/shots/T2/templates.mjs`（改 URL）、`clicks.mjs`、`interact.mjs`。

### 已知限制

1. **720 高的桌面视口**：横屏舞台约 796px 宽（24px 字显示为约 10px），竖屏约 276px 宽。这是“刻度条必须首屏可见”带来的结果，全屏可以补足（见 2.2）。如果以后要求更高，可以考虑在短视口把站点顶栏改为滚动隐藏（会影响全站导航，T2 没有做）。
2. **全屏中焦点在 Demo 里时按 F 不会退出**：按键在 Demo 窗口里，父页面收不到。Esc 由浏览器处理，不受影响；伪全屏的 Esc 站点在 Demo 窗口里也监听了。
3. **Esc 退出原生全屏**无法在无头浏览器里用按键验证（浏览器加速键），测试用 `exitFullscreen()` 代替；退出后的状态同步走的是同一个 `fullscreenchange` 处理。
4. 全屏空闲时 `cursor: none` 只作用于浮层区域；Demo 内的光标由 Demo 自己决定。
5. 旧 Demo 的 iframe 地址也会带 `&orient=…`（被忽略，无副作用），这样迁移后不需要改站点。
